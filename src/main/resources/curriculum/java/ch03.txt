@lesson J3.1 | Anatomy of a Java program
book: Chapter 3, section 3.1
@card read | The smallest program
text: Every Java program lives inside a **class**. Execution starts in `main`.
code:
public class Greeter {
    public static void main(String[] args) {
        System.out.println("Ready to learn Java");
    }
}
@end
text: Java is **case-sensitive**: `Main` and `main` are different names.
@card read | Reading the pieces
text: - `public`: other code may use it (an access modifier).
text: - `class Greeter`: a class name, written in CamelCase.
text: - `static void main(String[] args)`: the entry point; `void` means it returns nothing.
text: - `{ }` braces delimit blocks. Every statement ends with `;`.

@lesson J3.3 | Primitive types
book: Chapter 3, section 3.3
@card read | Eight primitive types
text: Integers: `byte` (8 bits), `short` (16), `int` (32), `long` (64).
text: Floating point: `float` (32), `double` (64). Character: `char` (16-bit UTF-16 code unit). Logic: `boolean` (`true`/`false`).
text: Use `int` and `double` unless you have a reason not to.
@card read | Literals
code:
long big = 4_000_000_000L;  // L suffix for long; _ for readability
int hex = 0xCAFE;           // hexadecimal
int bin = 0b1010;           // binary
float f = 3.14F;            // F suffix for float
double d = 3.14;            // double by default
char c = 'A';               // single quotes for char
@end
@card quiz | Which type would you use for a value like 3.75?
option: int
option: char
option*: double
option: boolean
explain: double is the default floating-point type. float has less precision and needs an F suffix.
@card quiz | What does this line need to compile? long x = 9000000000;
option: Nothing, it is fine
option*: An L suffix: 9000000000L
option: A cast to int
explain: An integer literal without a suffix is an int. 9 billion does not fit in an int, so it needs L.
@card read | boolean is not a number
text: In Java you cannot use an `int` as a condition. `if (x)` does not compile when `x` is an int; write `if (x != 0)`.
text: `double` cannot represent some decimals exactly: `2.0 - 1.1` prints `0.8999999999999999`. For money, use `BigDecimal` (lesson J3.12).
@card fix | Integer as condition

@end

    System.out.println("not zero");
}
@end

@lesson J3.5 | Operators
book: Chapter 3, section 3.5
@card read | Arithmetic
text: `+ - * /` and `%` (remainder). Integer division **truncates**: `7 / 2` is `3`, `7 % 2` is `1`.
text: If either side is a double, the result is a double: `7 / 2.0` is `3.5`.
code:
int q = 17 / 5;     // 3
int r = 17 % 5;     // 2
double d = 17 / 5.0; // 3.4
@end
@card quiz | What is the value of 9 / 2 in Java?
code:
int result = 9 / 2;
@end
option: 4.5
option*: 4
option: 5
explain: Both operands are ints, so the division truncates toward zero.
@card read | Math, casts and conversions
code:
double root = Math.sqrt(16);      // 4.0
double p = Math.pow(2, 10);       // 1024.0
double x = 9.997;
int n = (int) x;                  // 9: cast truncates
int rounded = (int) Math.round(x);// 10
@end
text: Widening (int to double) is automatic. Narrowing (double to int) needs an explicit **cast**.
@card quiz | What is (int) 3.99?
option*: 3
option: 4
option: 3.99
explain: A cast to int simply drops the fractional part.
@card read | Shortcuts and comparisons
code:
x += 4;      // x = x + 4
n++;         // add 1 (also n--)
a == b       // equal?    a != b  // not equal?
a < b && b < c   // AND, short-circuit
a < b || flag    // OR, short-circuit
!done            // NOT
int max = (a > b) ? a : b;  // conditional operator
@end
@card quiz | With && , when is the right side evaluated?
option: Always
option*: Only when the left side is true
option: Only when the left side is false
explain: && short-circuits: if the left side is false the result is false, so the right side is skipped. That is why x != 0 && 1 / x > 0 is safe.

@lesson J3.6 | Strings
book: Chapter 3, section 3.6
@card read | Strings are objects
text: A `String` is a sequence of characters. Strings are **immutable**: methods return new strings, they never change the original.
code:
String greeting = "Hello";
String s = greeting.substring(0, 3);  // "Hel" (end index excluded)
int n = greeting.length();            // 5
char first = greeting.charAt(0);      // 'H'
String all = "Java" + 11;             // "Java11"
@end
@card quiz | What is "Hello".substring(1, 4)?
option: "Hell"
option*: "ell"
option: "ello"
option: "Hel"
explain: substring(begin, end) includes begin and excludes end: characters 1, 2 and 3.
@card read | Never compare strings with ==
text: `==` checks whether two references point to the **same object**. To compare contents use `equals`.
code:
if (input.equals("yes")) { ... }           // correct
if (input.equalsIgnoreCase("YES")) { ... } // ignores case
if (input == "yes") { ... }                // BUG: may be false!
@end
@card fix | String comparison bug

}
@end
answer:
String command = new String("quit");

    System.out.println("bye");
}
@end
@card read | Empty, null and useful methods
text: `""` is an empty string (length 0). `null` means "no object at all": calling a method on it throws `NullPointerException`.
code:
if (str != null && !str.isEmpty()) { ... }
"  trim me ".strip();        // "trim me" (Java 11)
"a,b,c".split(",");          // ["a", "b", "c"]
"java".toUpperCase();        // "JAVA"
"banana".indexOf("an");      // 1
String.join("/", "a", "b");  // "a/b"
"ab".repeat(3);              // "ababab" (Java 11)
@end
@card quiz | Why write str != null && !str.isEmpty() in this order?
option: It is faster to type
option*: If str is null, the right side never runs, so no NullPointerException
option: isEmpty must always come last
explain: && stops at the first false. Checking null first protects the method call.
@card read | Building strings efficiently

@lesson J3.10 | switch, break and continue
book: Chapter 3, sections 3.8.5-3.8.6
@card read | The classic switch
text: Each `case` needs a `break`, otherwise execution **falls through** to the next case.
code:
switch (choice) {
    case 1:
        System.out.println("one");
        break;
    case 2:
        System.out.println("two");
        break;
    default:
        System.out.println("other");
}
@end
@card quiz | choice is 1 and there are no break statements. What prints?
code:
switch (choice) {
    case 1: System.out.println("one");
    case 2: System.out.println("two");
    default: System.out.println("other");
}
@end
option: one
option*: one, two and other
option: other
explain: Without break, execution falls through every following case. This is a common bug.
@card read | Modern switch (Java 14+)
text: The arrow form has no fall-through and can produce a value.
code:
String size = switch (n) {
    case 1, 2 -> "small";
    case 3 -> "medium";
    default -> "large";
};
@end
@card read | break and continue
text: `break` leaves the loop immediately. `continue` skips to the next iteration.
code:
for (int i = 0; i < 10; i++) {
    if (i % 2 == 0) continue;   // skip even numbers
    if (i > 7) break;           // stop after 7
    System.out.println(i);      // 1 3 5 7
}
@end
@card fix | Add the missing break

}
@end
answer:

@lesson J3.12 | Big numbers
book: Chapter 3, section 3.9
@card read | BigInteger and BigDecimal
text: When `long` is too small or `double` is not exact enough, use `java.math.BigInteger` and `BigDecimal`.
text: They are objects, so you use methods instead of operators.
code:
BigDecimal price = new BigDecimal("19.99");
BigDecimal total = price.multiply(new BigDecimal("3"));  // 59.97 exactly
BigInteger huge = BigInteger.valueOf(2).pow(100);
@end
@card quiz | Why create BigDecimal from the string "0.1" instead of the double 0.1?
option: Strings are faster
option*: The double 0.1 is already inexact; the string keeps the exact value
option: BigDecimal has no double constructor
explain: new BigDecimal(0.1) captures the binary approximation 0.1000000000000000055... Use the String constructor or BigDecimal.valueOf.
